#### P1-01 · เขียน Problem Statement - อธิบายปัญหาที่แอปต้องการแก้ไข

- ผู้ใช้งานที่ต้องการบริหารจัดการเงินส่วนบุคคลจำเป็นต้องบันทึกรายรับและรายจ่ายอย่างสม่ำเสมอ แต่การจดบันทึกด้วยตนเองอาจทำให้ติดตามข้อมูลย้อนหลังและสรุปภาพรวมทางการเงินได้ยาก จึงต้องการพัฒนาเว็บแอปพลิเคชันที่ช่วยบันทึกรายรับและรายจ่าย จัดหมวดหมู่ คำนวณยอดเงิน และแสดงรายงานสรุปตามช่วงเวลาในรูปแบบกราฟ เพื่อให้ผู้ใช้สามารถตรวจสอบสถานะทางการเงินของตนเองได้สะดวกขึ้น

#### P1-02 · กำหนด Project Goals - ระบุเป้าหมายที่วัดผลได้

| เป้าหมาย                           | เกณฑ์วัดผล (ตัวอย่าง)                                                                                      |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| บันทึกรายการได้สะดวก   | เพิ่มรายการได้ภายใน 1 นาทีในการทดสอบ                                                        |
| คำนวณยอดเงินถูกต้อง     | Test ครอบคลุมกรณีหลักและกรณีขอบของการคำนวณ                                              |
| แสดงรายงานได้                 | สรุปรายรับ รายจ่าย และยอดคงเหลือรายสัปดาห์ เดือน และปีได้ถูกต้อง |
| ปกป้องข้อมูลส่วนบุคคล | ผู้ใช้ไม่สามารถอ่านหรือแก้ไขข้อมูลของบัญชีอื่นได้                           |
| คุณภาพ Backend                       | มี Unit Test และ Integration Test สำหรับ Business Logic และ API สำคัญ                                     |

#### P1-03 · กำหนด Target Users - ระบุกลุ่มผู้ใช้และสถานการณ์ใช้งาน

- กลุ่มเป้าหมาย: บุคคลทั่วไปที่ต้องการติดตามรายรับและรายจ่ายส่วนตัว
- สถานการณ์ใช้งาน: บันทึกรายจ่ายประจำวัน ตรวจสอบรายการย้อนหลัง และสรุปค่าใช้จ่ายปลายเดือน
- รูปแบบการใช้งาน: ผ่านเว็บเบราว์เซอร์ โดยผู้ใช้แต่ละคนมีบัญชีและข้อมูลของตนเอง รองรับการเปิดผ่านโทรศัพท์มือถือและคอมพิวเตอร์

#### P1-04 · กำหนด MVP Scope - แยก Must-have, Should-have และ Out of Scope

MVP Scope

- **Must-have**
  - สมัครสมาชิก เข้าสู่ระบบ และออกจากระบบ
  - สมัครสมาชิก เข้าสู่ระบบ และออกจากระบบ
  - เพิ่ม แก้ไข ลบ และดูรายการรายรับรายจ่าย
  - กำหนดประเภทรายการและหมวดหมู่
  - คำนวณรายรับ รายจ่าย และยอดคงเหลือ
  - กรองประวัติตามช่วงวันที่และหมวดหมู่
  - รายงานสรุปรายสัปดาห์ รายเดือน และรายปี
  - กราฟแท่งเปรียบเทียบรายรับและรายจ่าย
  - แยกข้อมูลระหว่างผู้ใช้และตรวจสอบสิทธิ์ทุก API
- **Should-have**
  - ค้นหารายการด้วยคำสำคัญ
  - แบ่งหน้า (Pagination)
  - ส่งออกรายงานเป็น CSV
  - ปรับปรุงประสบการณ์ใช้งานบนมือถือ
- Out of Scope
  - เชื่อมต่อบัญชีธนาคาร
  - สแกนใบเสร็จด้วย OCR
  - ตั้งงบประมาณรายเดือน
  - รองรับหลายสกุลเงิน
  - วิเคราะห์พฤติกรรมทางการเงินด้วย AI

#### P1-05 · ประเมิน Technical Feasibility - เลือก Stack และประเมินเวลา/ข้อจำกัด

1. **Technology Stack**

| ส่วนประกอบ | เทคโนโลยี                                          |
| -------------------- | ----------------------------------------------------------- |
| Frontend             | React + TypeScript                                          |
| Backend              | Java LTS + Spring Boot                                      |
| Security             | Spring Security + JWT หรือ session-based authentication |
| Database             | PostgreSQL                                                  |
| Database Migration   | Flyway                                                      |
| Testing              | JUnit 5, Mockito, Spring Boot Test                          |
| Environment          | Docker + Docker Compose                                     |
| Version Control      | Git + GitHub                                                |
| Project Management   | Notion หรือ GitHub Projects                             |

1. **ประเมิน Technical Feasibility**

| ประเด็น                               | ผลประเมินเบื้องต้น                                                                                  |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| ความเป็นไปได้ทางเทคนิค | สูง — เป็นระบบ CRUD และการสรุปข้อมูล                                                      |
| ความซับซ้อนของ Business Logic  | ปานกลางถึงสูง                                                                                            |
| ความซับซ้อนของ Database        | ปานกลาง เพราะมีความสัมพันธ์ระหว่างผู้ใช้ หมวดหมู่ และธุรกรรม |
| ความปลอดภัย                       | ปานกลางถึงสูง ต้องแยกข้อมูลแต่ละบัญชีให้ถูกต้อง                         |
| การ Deploy                                | ปานกลาง ต้องตั้งค่า Environment Variables และ Database                                           |
| ค่าใช้จ่าย                         | เริ่มต้นได้ด้วยเครื่องมือ Open Source แต่ Hosting อาจมีค่าใช้จ่าย/         |

1. **ประเมินเวลา**

- ยังประเมินไม่ได้  (~มากกว่า 6 เดือน)

| งาน                                                    | ประมาณการเบื้องต้น |
| --------------------------------------------------------- | ------------------------------------ |
| วิเคราะห์ Requirement และออกแบบระบบ | 1–2 สัปดาห์                  |
| ออกแบบ Database และ API                          | 1–2 สัปดาห์                  |
| พัฒนา Backend และ Authentication                  | 3–5 สัปดาห์                  |
| พัฒนา Frontend                                       | 2–4 สัปดาห์                  |
| Integration และ Testing                                | 2–3 สัปดาห์                  |
| Deployment และ Documentation                           | 1–2 สัปดาห์                  |

#### P1-06 · ระบุ Risks - เช่น Security, ข้อมูลการเงิน, เวลาพัฒนา

| ความเสี่ยง                               | โอกาสเกิด | ผลกระทบ | แนวทางรับมือ                                    |
| -------------------------------------------------- | ------------------ | -------------- | ----------------------------------------------------------- |
| ผู้ใช้เข้าถึงข้อมูลคนอื่น | ปานกลาง     | สูง         | Authorization และ Ownership Tests                        |
| คำนวณยอดเงินผิด                     | ปานกลาง     | สูง         | ใช้ `BigDecimal` และทดสอบขอบเขต          |
| Scope บานปลาย                               | สูง             | ปานกลาง | กำหนดเกณฑ์รับงานและล็อก MVP          |
| Database Migration ผิดพลาด                  | ปานกลาง     | สูง         | Flyway และทดสอบ Migration                           |
| Deployment ไม่สำเร็จ                      | ปานกลาง     | ปานกลาง | ทดสอบบน Environment ใกล้เคียง Production    |
| ไม่มีเวลาทดสอบเพียงพอ         | ปานกลาง     | สูง         | กำหนดเวลาสำหรับ Testing ตั้งแต่ต้น |

#### P1-07 · สร้าง Repository และ Project Board

สิ่งที่ควรมีเพื่อปิดงานนี้ ได้แก่

- GitHub Repository พร้อม `README.md`
- `.gitignore` ที่เหมาะกับ Java, Node.js และ IDE ที่ใช้
- `docker-compose.yml` สำหรับ Environment ที่วางแผนไว้
- ไฟล์ `.env.example` โดยไม่มี Secret จริง
- Notion Project Board หรือ GitHub Projects ที่มี Task แบ่งตาม Phase
- Issue สำหรับงานถัดไป พร้อมสถานะและเกณฑ์การทำงานให้เสร็จ
